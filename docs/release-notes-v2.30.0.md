# ReadFlow v2.30.0 · 思考强度可调 + 文案瘦身 + 阅读器三处修复

## 1. 关键修复：AI 思考强度此前一直是"关闭"状态

- 根因：检索词规划里 `thinkingLevel: 'output'` 是**任务名不是思考档位**，底层遇到非法值会静默降级为 `disabled` —— 搜索规划一直在"不思考"跑。
- 现在：新增「AI 思考强度」设置（**快 / 标准 / 深入**，默认标准；Hive 持久化，位置：找材料 → 筛选 → AI 思考强度）。
  - 规划/补救轮：快=disabled、标准=low、深入=high
  - AI 改写：快=low、标准=high、深入=max
- 4 处调用点统一读取：自由搜规划、按需搜规划、补救轮、AI 改写；AI 改写结果卡显示「思考强度:标准/深入」，用户能看到实际用了哪档。
- 全库已无非法 `thinkingLevel` 值。

## 2. 阅读器三处修复

- **追问抽屉读不到材料**（根因）：正文按 2500 词一块入库，2011 词材料只有一块（≈1.2 万字符），旧逻辑 `body.length + t.length > 6000` 第一次循环就 break → 传给 AI 的正文为空。已抽纯函数按字符截断，整篇优先当前在读小节 + 全文开头，保证非空；单段追问保留本段+译文+邻段。
- **追问抽屉常置功能删除**：只保留「梳理内容」「评价材料」两个快捷键（识图/写译链路不受影响）。
- **丰富形式不再跳文末**：打开形式 sheet 前后保持阅读位置（<1px 变化），不再有"按了不知道去哪"。
- **一键回顶/回底**：点右上 % 胶囊 → 「回到顶部 / 跳到底部」，320ms 平滑滚动，进度照常记录。

## 3. 文案瘦身（全 App 灰字）

- 助理/我的/关于、输出/写译、找材料、频道页：删重复解释、长句压成一行（≤30 字）、灰字统一两类（必要说明一句 + 错误原因）；保留真实数据/来源/难度/成本/时间。
- 组件层统一：`briefOneLine()`（首句 ≤30 字）、说明 11px 一行、空态一句说明+一个动作。
