# 材料中心 / 找材料 · 问题诊断与整改方案（2026-11-05，待选型）

> 用户 11/05 反馈的 4 个结构性问题 + 找材料质量问题。先说清根因，再给 3 个方案；
> 选定后我再动生产代码，不再"边猜边发"。

## 一、根因（不是零散 bug，是三处结构没定）

### 1. 二级板块点进去，"我点过的材料"堆在下面，不能收/不能管

- 现在每个板块页(按题材/形式/场景)的内容 = `MaterialLibrary.shelf()`，
  也就是**你看过/导入过的材料**，按需求排序后一直往下排。
- 真正的"发现/推荐"结果只在「按需求找材料」页的当次内存里，**从不落库、不落分类**。
- 所以每个板块都变成"历史材料的无限竖列"，既不能收起，也没有编辑/删除入口
  (编辑/删除只在「我的材料库」里，用户不会想到要回那里)。

### 2. AI 补长尾的结果留不下来，下次进入重新搜

- `MaterialDiscovery` 的 `DiscoveryRun` 是页面 State 里的临时对象；离开页面即丢。
- 想"再看一次刚才找的那批/继续找更多"，只能重新花一次官方搜索的钱。

### 3. 只有"重新找"，没有"继续找更多"、没有分页

- 发现流水线是**一次性的**：一次计划 → 一轮搜索 → 抓 8 篇 → 结束。
- 所以结果页只有「再找一次」；"更多"= 从头再跑一遍，重复 URL 还要再过滤一次。

### 4. 找到 PDF 点不进去

- 结果卡的「开始读」只在**已抓到正文**时可用；PDF 多数抓不到正文 → 按钮禁用。
- 卡片上没有「打开原文/打开 PDF」的兜底入口 → 用户看到结果却点不动。
- 本轮已先补「打开原文/打开 PDF」(直接调系统浏览器)；后续再做 PDF 正文提取。

### 5. 思考过程一直铺在页面上

- 搜索时间线 `SearchTimeline` 直接铺在结果上方，且不折叠。
- 本轮已改为「搜索过程 · N 步」可折叠卡片，跑完自动收起。

## 二、三个方案（请选一个）

### 方案 1 · 最小改动：发现优先 + 历史折叠（1~2 天）

每个板块页从上到下：
1. **发现区**：本次/上次搜索结果(分页，每页 10 条，「继续找更多」追加)；
2. **我保存/看过的**：默认折叠的一行「我的材料 · N 篇」，点开展开历史；
3. 历史材料可直接编辑/删除/收起，不再默认堆满页面。

- 快照：发现结果按"板块+检索词"存到 Hive，下次先显示上次结果 + 更新时间。
- 优点：改动小、老数据不用迁移、立刻可见效果。
- 缺点：发现和历史是两套列表，"保存"只是快照，不是真正的材料实体。

### 方案 2 · 频道化（推荐，3~4 天）

每个大分类变成一个**频道页**，顶部两个 Tab：

| Tab | 内容 | 能力 |
|---|---|---|
| **发现** | 真实爬取结果(分组:教材/真题/书籍/论文/文章) | 分页加载、继续找更多、保存到我的、打开原文/PDF |
| **我的** | 该频道下已保存/看过的材料 | 编辑中文名/分组/删除/隐藏、离线读、按进度排 |

- 发现结果可「保存到对应分类」→ 落成真实材料实体(可在材料库管理，离线可读)；
- 未保存的发现结果按频道存"搜索快照"，下次进入先显示，可刷新；
- 材料库保留，作为全局管理入口(浏览记录/外部导入/已隐藏)。
- 优点：结构清楚，用户预期"这个分类里有什么"和"我存了什么"分开；持久化/管理自然。
- 缺点：需要新增发现快照存储 + "保存到分类"的入库通道，工作量中等。

### 方案 3 · 工作台（重，5~7 天）

所有大分类共用一个"找材料工作台"：顶部搜索/需求，左侧筛选(题材/形式/场景/难度)，
右侧结果流无限加载；找到的东西默认进"待读箱"，材料库变成统一管理中心
(待读/在读/已读/隐藏)。优点是最有工具感、最"系统"；缺点是信息密度高、改动大。

## 三、找材料质量专项（与方案解耦，都会做）

1. **分页/继续找更多**：一次检索计划生成 6~8 条 query(含系列名/考试名)，按"轮"执行；
   每轮抓 8 篇，结果按 URL 去重后追加；「继续找更多」= 执行下一轮 + 新 query。
2. **结果分组**：按 教材 / 真题 / 书籍 / 论文 / 文章 五个组分开展示，组内按难度排序。
3. **持久化**：方案 2 下"保存到我的"落库；未保存结果按频道存快照(带更新时间/花费)。
4. **PDF 处理**：检测 `.pdf` → 先试 DeepSeek 官方 fetch 提取纯文本；失败则「打开 PDF」
   外部浏览器兜底；PDF 正文提取成功的就正常入库。
5. **渠道矩阵(本机实测)**：
   - Project Gutenberg：可直连，公版书全文；
   - RSS( NPR / ScienceDaily / NASA / TED / BBC LE / VOA LE)：可直连，外刊文章；
   - Internet Archive / OpenLibrary：本机不可达 → 只能通过 DeepSeek 官方 fetch；
   - 教材/真题/教辅/中文站：**只能靠 DeepSeek 官方搜索 + fetch**（服务端抓取），
     所以官方 Key 的质量 = 找材料质量的上限。
6. **版权口径**：用户明确个人学习使用，检索层不再过滤"非公版"；只保证每条都有真实 URL。

## 四、阅读器

方案 A 已按选型落到生产阅读器(暖纸面/大标题/悬浮玻璃底栏/译文左竖线注释)，
本版安装包可验收。

## 五、执行顺序（选定方案后）

1. 先做方案里的 P0：分页/继续找更多 + 结果分组 + 保存到分类；
2. 再做 PDF 正文提取与快照持久化；
3. 最后做材料库与发现区的编辑/删除/隐藏对齐；
4. 每步只发"你确认过的主题"，不再混着发。
