## 二、训记的"本质"是什么(已调研,只学这些)

从公开资料(小程序版说明 + 产品迭代记录)提炼的设计原则:

| 原则 | 训记怎么做 | ReadFlow 对应要改什么 |
|---|---|---|
| **打开即行动** | "一进入训记,马上就能开始训练记录,无需多余的过程" | 首页不该是"卡片墙";打开就该有**一个主行动**(今天先做这件) |
| **预判下一步并预填** | 输入完一组自动加下一组并预留空格;长按整组复制 | 复习/阅读/听写:自动准备好下一步(继续上次材料、继续未完成的复习) |
| **数据就在手边** | 长按动作卡看历史容量;日历上直接显示当天容量 | 长按词条/材料即可看历史(复习历史、出现记录),不用跳三层 |
| **按场景设计输入** | 自重(体重)/力量(kg·lbs)/有氧(分钟·次)三套单位模型 | 我们的输入也应分场景(拍照/粘贴/检索),而不是一堆并列入口 |
| **状态可恢复** | 组间计时器双击关闭自动存时间,下次接着算 | 进行中的事(复习进度、阅读位置、听写轮次)都要能"接着来" |
| **简单明了的操作流** | 大量手势(代价:需要讲解)——**这一点我们反着学**:手势必须可发现 | 不做隐藏手势;关键操作要有可见按钮 |
| **战绩可视化** | 训练容量图表 + 分享 | 我们的周报/进度可视化要更"一眼看懂",而不是堆文字 |

**反例(明确不学)**:深色不一定适合学习类阅读场景;训记的信息密度是为"训练中单手速记"设计的,ReadFlow 的阅读/复习是**长时间阅读**场景,密度要低、字号要够、留白要够。
