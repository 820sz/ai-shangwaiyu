## 二、动手前的现状分析(根因,已读代码确认)

### 2.1 第 1 条:追加图片闪退 —— 两条真实原因

| 位置 | 问题 |
|---|---|
| `process_chat.dart _addMoreImages` | `ImagePicker().pickMultiImage(imageQuality: 85)` **没有 maxWidth** —— 首页相册选择用的是 `imageQuality: 50, maxWidth: 1024`,追加这条路拿的是**原图**(12MP≈48MB RGBA/张)。随后 `_imageToDataUri` 要把每张整图 base64 进内存、`VisionImagePrep` 再解码切块 → **3~4 张就 OOM,表现就是"卡死→闪退"** |
| 同上 | 追加没有**数量上限**,用户可以无限追加;请求体随张数线性膨胀(服务端也会拒) |
| `_startStreaming` 成功分支 `_imageGroupKeys.clear()` 后重建全部 key | 第一遍结果的 widget 仍挂在旧 key 上 → key 被换掉会重建整棵结果树,叠加图片解码,进一步放大卡顿 |

### 2.2 第 2 条:中文材料 → 词汇板块"乱" —— 是**中英两条目重复 + 卡片头不一致**

截屏里同一个内容出现两张卡:
- 卡 1「等级制度」→ 下面是 `hierarchy`(**中文当头、无词性 chip**)
- 卡 2「hierarchy」→ chips `word` `n.` → 释义「等级制度」

即 v2.6 起"中文批注单独成条"的设计:**中文批注一条、英文原词一条**,两条内容重叠;
而且两条的**卡片头一个中文一个英文**,视觉上就是"又乱又重复"。

### 2.3 第 4(1) 条:复习「认识」卡住 —— 一行早退

`review_screen.dart _mark()`:
```dart
final previous = _marks[id];
if (previous == level) return;   // ← 重复点同一档位直接 return
...
if (level == 2) _next();
```
从下一张退回来时该词已被标记为「认识」,再点「认识」→ 命中这行**直接 return,不 `_next()`** → 卡住。

### 2.4 第 4(2) 条:单词被拆行 —— 卡片背面的 Row 让徽标抢宽度

`_cardBack()`:`Row[ Expanded(Text(词, titleLarge)), if (markedLevel) _markBadge() ]`,
徽标文案「已标记:不认识 · 新词」很宽 → 词被挤成两行(`primordi` / `al`)。
正面 `_cardFront` 也没做长词自适应(固定 headlineMedium)。

### 2.5 第 5(1) 条:助理"已完成"按钮溢出 —— 两个按钮都没 Expanded

`tutor_home.dart _buildPrimaryAction()`:一行里放两个**定宽按钮**
(「已完成,点这里取消」带图标 + 「取消完成」),`Row` 里没有 `Expanded/Flexible`
→ 总宽超过卡片宽度 → 文字溢出卡片、第二个按钮被裁(截屏就是这样);
而且 done 时**两个按钮做的是同一件事**(都 `_reopenTask`),本身就是冗余。

### 2.6 第 6(3) 条:逐段翻译"无法使用" —— 是**批量策略**在长材料上等于不可用

`material_reader_screen._toggleTranslation()`:一次性按 8 段一批**把全文翻完**才逐段显示。
一本书动辄 200+ 块 → 需要 25+ 次串行请求,每块还是最多 2500 词的整段;
用户看到的就是"一直转圈/一直显示翻译中",体验上等于"不能用"。
**改法**:改成**按需翻译**(只翻当前可见的几块,滚动到哪翻到哪)+ 顶部进度 + 单块失败可单独重试。

### 2.7 第 8 条:追问抽屉"花" —— 颜色来源

追问抽屉的 AI 回复走 markdown/富文本渲染,标题/列表/引用/代码各一套色
(主色 + 琥珀 + 成功绿 + 危险红同时出现在一段话里)。**改法**:回复正文只留两种颜色
(正文色 + 一处强调色),其余靠字重/缩进区分。
