## 1. 我的理解：用户的学习理论 → 软件骨架

### 1.1 理论四层 → 产品对应物（一一对应，不许错位）

| 理论层 | 用户原文（摘要） | 产品对应物 | 当前 App 的实际状态 |
|---|---|---|---|
| **L1 闭环** | 输入 → 输出 → 反馈 → 再输入 | 输入栏（读/听）→ 输出栏（写）→ 批改与错误档案 → 复习调度 → 回到输入 | ❌ **断链**：输出练习的结果没有回流到复习/助理；助理只能报"还有什么没做" |
| **L2 四能力** | 听、说、读、写；输入=听读，输出=说写 | 输入=读+听；输出=写（说暂不做，模型不支持）；**"背单词/复习"不是独立能力，是输出的最低阶（主动回忆）** | ⚠️ **错位**：复习页挂在「我的/助理」，被当成独立功能；输出只有「写词 + 写译」两格 |
| **L3 三要素** | 语音、词汇、语法 | 每个练习都要标注它练的是哪个要素：写词=词汇+语音（形音义）、写句=词汇+语法、写段/写篇=语法+篇章 | ⚠️ 要素**没有穿透到练习设计**：练习类型有，但没有"练的是什么"的映射与统计 |
| **L4 个性化** | 按个人目的加一点侧重；但**只能在前三层走完后做补充，不能是起点** | 需求采集（多选）→ 影响推荐排序与加权；**考试真题/教材回译是"补充层"，不是首页主入口** | ❌ 需求只影响一句提示词；考试目标字段 `goals` 是**死数据**（无人写入）；个性化=用户填表，无反馈闭环 |

### 1.2 用理论照一遍现在的 App：三个"不成立"

**① 输入不成立——"找材料"不是"按需求找材料"，是"固定源 + 关键词碰运气"**
- 现状（侦察实测）：AI 只把中文需求翻成英文检索词，**3 条 query 只用第 1 条**，模型点名的 `picks` 不参与检索；分类→源是写死的（书→Gutenberg、论文→arXiv、外刊→NPR…）；检索结果卡上的难度 `Lv` 是**按源类型猜的**（全部同款），真实难度要抓回正文才算；大陆可达的源实际只有 **NPR / arXiv / Gutenberg** 三个。
- 用户要的是：「用户偏好需求 → 提供材料」，材料要基于个性化、有配图、有来源、能备考。

**② 输出不成立——只有"写词 + 写译"两格，题目与"读过的东西"无关，反馈不回流**
- 现状：「练」= 拼写/听写等词级练习；「写」= 写译批改 + 写译记录；口语标注"敬请期待"。
- 缺口：没有**阶梯**（词→句→段→篇）、没有**语境化题目**（从你刚读的材料出题）、没有 **rubric 维度评分**、没有"结果 → 错误标签 → 复习队列 → 助理诊断"的回路、没有针对目标考试的**针对性材料**。

**③ 助理不成立——不是"分析得浅"，是"没有数据可分析"**
- 现状（待侦察确认）：诊断靠规则出"还有什么没做"；`goals` 死字段、`reading_wpm`/`vocab_inferred` 无写入、语法薄弱点无数据、输出练习无记录 → 只能报"单词 xx 没复习"。
- 结论：**要先做输出闭环，助理才有米下锅**。顺序上输出在助理之前。

**④ 视觉不成立——不是"设计 token 不够细"，是"没有图形资产"**
- 全 App 除鲸鱼尾外没有一张自绘图形；材料封面是程序化色块 + 文字；所有材料/内容同一种横卡；空态、数据、分类全用 Material 图标 + 文字撑。→ 怎么改卡片都是"色块 + 文字 + 列表"。

**⑤ 材料中心单独点名（2026-11-01 用户原话）**
> "这个材料中心真的彻头彻尾的烂，不管是功能还是给的材料，还是爬取能力，还是各种小bug（比如里面的文章阅读器的翻译功能永远没法用，翻译进度永远是死的），还是前端排版都是彻头彻尾的烂而且好几轮没修改出效果的——但这个功能却恰巧是输入来源的大头。"
- 所以材料中心**不是"顺手改进"，是重做**：功能（需求驱动选材/筛选/书架/材料库）、给的材料（真实图/来源/难度可靠）、爬取能力（Search/Fetch + 多源）、小 bug（阅读器翻译与进度、打开失败、重复条目…）、前端排版（图形资产 + 形态分流）一个都不能少。
- **阅读器翻译"永远没法用、进度永远死的"列为批 2 首要根因排查项**（先摊开实现与日志，再修）。

## 2. 我的主张（方案本体）

### 2.1 信息架构：四栏职责重新锚定（底栏改名是整个改造的"总纲动作"）

```
                 ┌──────────── 闭环 ────────────┐
                 ↓                              │
  【输入】读 / 听          【输出】写           【反馈】
  真实语料 i+1             四阶：词→句→段→篇      批改 · 错误档案 · 复习 ·
  拾词入语境               题目来自"你读过的"     能力画像 · 下次推荐
                 └──────────── 【助理】调度 ────┘
```

| 栏 | 职责 | 首页"一屏一个主行动" |
|---|---|---|
| **输入**（原"材料"） | 读 + 听：找材料 / 继续读 / 拍照导入 / 听力 | 「今天输入什么？」→ 继续读（在读进度）/ 换新材料（需求驱动）/ 拍一页（识图）/ 听一段 |
| **输出**（原"练习"） | 写：四阶练习 + 写译批改 + 反馈 | 「今天写什么？」→ 今日建议（来自输入拾词与错误档案）+ 四阶入口 + 待复盘 |
| **我的** | 资产与记录：词本、收藏、统计、设置、导出 | 数据面板（真实数据，不造分） |
| **助理** | 调度：诊断 / 需求 / 任务 / 复盘 | 今日任务卡 + 现状五维 + 会话入口 |

**关键取舍（需要用户点头）**
1. **复习（SRS）从「我的/助理」移入「输出」**，作为"写词阶"（主动回忆=输出），同时在助理任务卡和"我的"保留快捷入口。理由：理论里它属于输出，而且它是"从阅读拾词"长出来的，不是独立背单词 app。
2. **识图从输入首页的"主角"降为"一种输入方式"**（第一屏主行动是"今天读什么"，拍照/导入是并列入口卡，不删功能）。理由：理论的输入=听读，识图只是"把纸质/屏幕内容变成材料"的手段。
3. **"说/口语"明示不做**（没有语音识别就不给发音分，不编造），保留"敬请期待"占位但降权。

### 2.2 输入模块：需求 → 检索计划 → 并发抓取 → 难度打分 → AI 加工 → 解释性推荐

**这是本轮最大的技术杠杆：DeepSeek 2026-10-17 起开放了官方 Search / Fetch API**（已核实官方文档）：
- `POST https://api.deepseek.com/v1/tools/search`：真实网页检索，返回 `title/url/snippet/summary/content/site_name/date/authority(0-4)/rerank_score(0-3)`，支持 `site:`/`lang:`/`after:` 等语法；
- `POST https://api.deepseek.com/v1/tools/fetch`：抓单页 → Markdown 正文；
- 计费：各 5 元/千次成功请求（失败/无结果不计费）；QPS search 100 / fetch 25；
- 模型 `deepseek-flash` = **DeepSeek-V4.1-Flash-1017**：1M 上下文、384K 输出、Tool Calls、JSON Output、原生图像理解（已核实官方文档与价格页）。

**新引擎（替换现在的"固定源+关键词"）**
```
① 需求（结构化）        exam/goals/兴趣/难度带/单篇时长/形态/黑名单
        ↓
② 检索计划（AI，JSON）  queries[](全用上) + sources[] + 难度/篇幅约束 + avoid[]
        ↓
③ 并发执行（App，不跑模型） 公开源(RSS/API) + 官方 Search（长尾）
        ↓
④ 抓正文 + 本地难度打分   覆盖率/生词密度/CEFR/预计时长（零 API 成本，可复现）
        ↓
⑤ i+1 过滤与排序        95-98% 舒适区优先；过载(<90%)明确告知
        ↓
⑥ 卡片化（AI 只做表达）   中文标题/导读/推荐理由/预热词/读后题（不编正文）
        ↓
⑦ 入库 → 材料库 / 今日推荐 / 书架
```

**AI 该用/不该用（判定表）**

| 步骤 | 用 AI？ | 理由 |
|---|---|---|
| 需求 → 检索计划 | ✅ 强用（JSON Output） | 新一代模型的强项：把"我想读点 AI 科普，10 分钟"翻译成可执行检索计划 |
| 执行抓取 | ❌ 不用模型 | 模型不联网；抓取走 Search/Fetch 与公开源，App 编排 |
| 难度打分 | ❌ 本地算 | 词频表 + 覆盖率，零成本、可解释、可测试 |
| 挑哪几篇 / 推荐理由 | ✅ 用，但必须落在真实打分数据上 | 禁止"凭印象推荐" |
| 导读/预热词/读后题 | ✅ 用 | 真实语料优先，AI 只加工不代写正文 |

**两段式 agent（我的主张）**
- 主链路 = **确定性编排**（规划→抓取→打分→卡片），保证每次都有结果、可测、成本可预估；
- 补救链路 = **tool-calls 闭环**：候选不足/不相关时，把真实候选（带 url/authority/date）交给模型，让它决定"换什么 query、抓哪几条"，再回传结果出卡片。这一步用上新模型的 Tool Calls 能力，但**每条结果必须有 url 与来源**，无出处不进卡片。
- 成本要可见：一次"AI 找材料" ≈ 0.05~0.1 元（1 次 search + 3~5 次 fetch + 模型打分）。UI 上写清"会走几次网络/大约多少钱"——BYOK 用户很在意这个。

**难度：用户自选 + 软件同步调整（2026-11-01 用户补充）**
- 用户原话："需要让用户自选难度并软件同步调整，比如我是比较喜欢 i+100 的，因为这样可以短期获得效果形成正反馈"。
- 设计：难度档做成**显性可选项**，每档写清"是什么体验"：
  - **i+1（舒适）**：覆盖率 95-98%，几乎无阻力，适合长期积累；
  - **i+10（挑战）**：覆盖率 90-95%，需要预习词，适合想突破；
  - **i+100（爽/快速正反馈）**：生词多、读得"费劲但爽"，适合短期冲量。
- **同步**贯穿全 App：材料推荐/难度标签/预计时长/输出题目的难度/助理计划里的阅读任务，都读同一个难度档；用户改了档位，其他位置立刻同步，不是各写各的。
- **软件辅助调整**（不强制）：根据实际表现（读完率、查词密度、读后测验正确率、放弃率）给"建议调到 i+X"的提示，用户自己决定是否改——**档位永远是用户的选择**。

**推荐逻辑（用户点名的"重中之重"）**
```
推荐分 = 目标相关度（考纲词命中/题材）× i+1 匹配（覆盖率 95-98%）× 兴趣
        × 来源质量 × 时长匹配 × 新鲜度 × 多样性（同类不过载、形态轮换）
```
- **每条卡必须给"为什么推荐你读它"**：例：「覆盖率 96% · 命中你四级词表 12 个词 · 约 8 分钟 · 来源 NPR」——这就是用户要的"有指导性"；
- **闭环推荐**：读完 → 拾词 → 输出练习（从这篇材料出题）→ 复习正确率 → 回写难度与兴趣 → 影响下一次推荐；
- **加权机制**（落实 L4）：考试真题/教材回译等"针对性材料"作为**补充层**参与推荐加权与"今天建议"，但**不做门槛**——用户想直接练就能直接练（与输出四阶并行一致）。

**已有通道（别重复造）**
- `materials.cover_url` **已存在**（dbVersion 18，v2.11 加的：RSS 头图 / 公版书封面 / `og:image` 已落库），配图问题不是"没有通道"，而是**覆盖不全 + 兜底难看**：没抓到头图的条目就退化成程序化色块。→ 本轮做"覆盖增强 + 类型化自绘兜底"，不是重建通道。
- **考纲词表 assets 并不存在**（`assets/data/` 只有 `en_freq_50k.txt` 与 `en_10k_clean.txt`）。PLAN-2.0 说的"内置考纲词表（四六级/雅思/托福/考研）"**从未交付**。要做"距目标还差多少词""目标词命中率"，必须补这份公开词表（几 MB 内，需确认来源与许可）。

### 2.3 输出模块：四阶写作阶梯 × 三要素 × 语境化 × 反馈回流

**现状实锤（侦察已完成，详见 `docs/research/output-and-tutor.md`）**
- 输出 tab 实际只有：**词汇拼写**、**中→英句子回译**（两者题目 100% 从生词本捞，判分是"全等/词袋重合"）、**AI 自由写作批改**（没有题目、没有 rubric，模型自由给 0-100）、以及**藏在文章阅读器里**的 AI 抽句回译（提交后只变灰 + 总分）。口语是占位。
- 答题页**一套骨架套所有题型**（ListView + TextField + 底部全宽按钮），结果页都是"大分数 + 文本卡"；题型专属交互为 0。
- **数据孤岛（最关键）**：`drill_logs` / `writing_logs` / `exercises` 全都不进助理快照与周报；`error_tags` 只被"复习答错"和"读后测验"写入；`writing_logs` 的错处**不写 error_tags**。所以**即使你天天写译，助理仍会报"近 30 天只有输入没有输出"**。
- **可复用资产**：`drill_planner.dart` + `drill_catalog.dart`（8 目标出题偏好、3 档水平、六项加权组题、4 周大纲、自适应、日志派生统计，有单测）——这是重建输出模块的地基，**不推倒**；要退役的是写死 if/else 的答题页与旧 `exercises` 回译链路。

**这是本轮产品价值最高的地方。** 把"输出"从"两格功能"变成一条可走的路：

| 阶 | 单位 | 三要素重心 | 练习形态 | 题目来源（**必须有语境**） | 反馈 |
|---|---|---|---|---|---|
| **写词** | 词 | 词汇 + 语音（形-音-义） | 认词/拼写/听写/音→形/语境选词填空（把现有复习并入本阶） | 从你读过的材料里拾的词与原始句 | 对错 + FSRS 调度更新 |
| **写句** | 句 | 词汇 + 语法 | 中译英回译（已有内核）、句式改写/升级、错句纠错、连词成句、仿写 | 材料原句（回译/仿写）、你自己的错句 | 逐词差异 + 语法错误标签 |
| **写段** | 段 | 语法 + 篇章 | 摘要写作、读后续写、观点段、图表描述、段落翻译 | 刚读过的材料（摘要/续写/观点延伸） | rubric 维度分 + 错误标签 |
| **写篇** | 篇 | 篇章 + 语用 | 四六级写作/翻译、雅思 Task 2、学术摘要、应用文 | 目标考试材料（**AI 搜索/抓取 + 用户上传都支持**）/ 教材回译 | rubric + 分数环 + 逐条批改（已有能力） |

> **四阶是并行的，不是锁死的（2026-11-01 用户明确）**：任何人都能直接进任何一阶，不存在"写词过了才解锁写句"；软件只在"今天建议"里按需求与水平**推荐**起点，不阻止用户跳级。每个人的基础与目标不同，强制顺序就是死人逻辑。

**练习区 UI 必须形态不同（解决"单一同质化"）**
- 写词：卡片翻面 + 单行输入 + 即时反馈动画；
- 写句：左右对照（原句/你的翻译）+ 逐词差异高亮 + 语法标签；
- 写段：编辑区 + 右侧 rubric 进度（内容/结构/语言）；
- 写篇：三步工作台（① 选题目/拍手写 ② 批改 ③ 复盘），结果页 = 分数环 + 错误分类图 + 逐条错误卡（可追问）。

**针对性材料的来源（2026-11-01 用户已明确边界）**
- 用户原话："尽量是支持用户自行上传，也要发挥 AI 爬资源的能力，不用担心合不合法，能搞到才是最重要的，我这软件就自己和几个朋友用，又是开源，所以最大程度发挥 ds 新模型的找资源搜索能力。"
- 所以两条都做，且**不设法律门槛**：
  1. **AI 搜索/抓取**：用官方 `/v1/tools/search` + `/v1/tools/fetch` 找"四六级/考研/雅思写作翻译真题、新概念等教材课文、范文与评分标准"，抓到后结构化入库（`exercise_sets`：考试/年份/题型/section/来源 URL）；用户目标词表/年份可筛。
  2. **用户上传**：文本/图片/链接（现有 `material_import` 三通道）→ AI 切题 + 生成参考答案与 rubric。
- **仍守的两条工程边界**（不是法律，是体验）：不抓需要交互式验证码/登录墙的页面（技术上做不稳）；所有材料**保留来源 URL 与抓取时间**，便于追溯；付费内容不转发、只在本地缓存给自己用。
- 生成内容带 `verify_status`（待校对/已校对），AI 出的题与参考译文优先用"有来源的真题原文"，不凭空编题目来源。

**rubric 从哪来（针对性）**
- 四六级写作：内容切题 / 组织连贯 / 语言准确 / 词汇丰富 / 句式多样；
- 翻译：原文理解 / 译文准确 / 表达通顺；
- 每条 rubric 维度 → 错误标签（时态/冠词/搭配/中式英语…）→ `error_tags` 表 → 助理"语法薄弱点" + 复习队列。
- 成绩只报**可解释的维度分**，不造"综合能力分"。

**数据回流（闭环的关键）**
```
练习作答 → 结果落库（分数/rubric/错误标签）→ error_tags 累计与复发追踪
        → 复习队列（错词/错句）→ 助理诊断（语法薄弱点/输出量）
        → 下一次输入推荐（题材/难度/目标词）→ …
```

### 2.4 助理模块：从"提醒待办"变成"闭环调度器"

**现状实锤（详见侦察报告 §第二部分）**
- **多选**：`tutor_interview_screen.dart:44-48` 第 1 步（"你学英语最主要想用它做什么"）没有 `multi:true`，所以单选；`_finish()` 只写单值 `LearnerModel.goal`，**不写已有的多选字段 `goals`**；访谈页那个"想补充点什么"自由输入框，`_finish()` **根本不读 → 用户打的字直接丢弃**。旧画像页 `learner_profile_screen.dart:109-125` 也是单选。全库有**三套互不相通的目标写法**（`goal` 单值 / `goals` 多值 / 旧 `LearnerProfile.goal`）。
- **现状分析**：`TutorEngine.diagnose` 共 **11 条本地规则，其中 8 条是行为债/材料匹配**（复习堆积、生词本变收藏夹、输入没有输出、材料太难/太易、重复错题、速度慢、中断…），**没有一条给出分项能力值**。真正值钱的数据都在但没组装：词汇量测量（`vocab_estimator` 有 estimate/区间/CEFR/分档命中率，只写 Hive 显示一次）、FSRS 记忆状态、阅读 wpm/覆盖率、周报规则引擎（`weekly_report.dart` 只在「我的」页，助理读不到）。
- **学习任务**：`TutorEngine.planTasks` 是**纯模板 ≤4 条/天**，不可编辑、无自定义、无状态机；更严重的是主卡「开始」按钮**先勾完成再跳转**（`tutor_home.dart:518-523`）→ 完成数据不可信；没有复盘视图。
- **缺什么**：语法能力项（只有完整版测试 5 道语法题，错题不建档、不累积、不分项）、写作维度分、听力成绩、能力项时间序列。

**数据管道（先有数据，再谈分析）**
- 汇：`reading_sessions` / `material_progress` / `word_review` / `quiz_results` / `writing_logs` / `drill_logs` / `error_tags` / `learner_model`（**第一期就要把 drill/writing 接进快照**，这是消除"误报只有输入"的根子）；
- 算：词汇量 V̂ ± 置信区间（已有 `vocab_estimator`）、错误标签分布与复发率、阅读速度 wpm、输入/输出量趋势、目标词表差距；
- 出：**五维现状，每条 = 发现 + 证据 + 建议动作 + 一键跳转**；未测维度显示"待测 + 怎么测"，**绝不编数字**。

| 维度 | 数据来源 | 例子（每条都能点回数据） |
|---|---|---|
| 词汇 | 词汇量测试 + 复习记录 + 拾词 | 「估计词汇量 4,200（±350）· 四级词表覆盖 78% · 近 7 天新词 42 个，复习留存 81%」 |
| 语法 | 写译/回译批改的错误标签 | 「近 30 天 23 个错误中时态 8 次（复发 3 次）、冠词 5 次」 |
| 阅读 | 阅读会话 + 材料进度 | 「平均 178 wpm · 近 7 天精读 3 篇，覆盖率 96% 的 2 篇读完」 |
| 输出 | 练习记录 + rubric | 「本周写了 2 段 1 篇 · 结构分 3.2/5 · 未做四六级写作专题」 |
| 习惯 | 学习天数/连续/时段 | 「连续 6 天 · 晚间 21-23 点最活跃 · 输入:输出 ≈ 9:1（输出偏少）」 |

**需求询问**：多选（考试目标可多选：四六级/雅思/托福/考研；兴趣可多选）+ 时限 + 每日时长 + 材料形态偏好；写入 `learner_model.goals`（与练习中心同一口径，消灭三套写法），**立刻影响输入推荐**，不只是存着。

**学习任务**：AI 生成（带证据与预计时长）→ **用户可编辑/增删/排序/跳过** → 完成回填（带真实结果才算 done）→ 未完成次日结算进复盘 → 任务完成率/按时率进周报。任务状态机：`pending → active → done / skipped / expired`；事件落 `task_events` 不覆盖历史。

**复盘**：周报从"文本汇报"升级为"数据 + 指导"：本周输入/输出量、错误复发、任务完成率、计划 vs 实际、下周调整（配额/材料更换/薄弱点专项）；并新增指导规则（任务卡壳→拆小、计划过载→降量、能力停滞→换练法、输出缺失→修误报）。

### 2.5 前端视觉系统 v3：把"缺少图形资产"补上

六层，自底向上：

1. **图形资产层（新建 `lib/widgets/graphics/`，纯 CustomPainter，零新依赖）**
   - 12 套内容领域图形（同心轨道/峰线柱状/脉搏波/拱门/航线弧/字母解构…）；
   - 5 类材料封面（书=书脊+书皮、论文=网格+公式、新闻=头条排版、真题=考卷格、笔记=便签折角）；
   - 空态插画（漂浮书页/纸飞机/散落字母/放大镜）；
   - 数据图形（进度环/柱状/热力日历/趋势线）；
   - 纹样与背景（极淡几何纹，用于页面头图）。
2. **形态库 6 种**：Hero 大图卡 / 横卡 / 竖卡封面(3:4) / 网格块 / 列表行 / 图表卡——按内容类型选形态（文章/书/新闻/真题/音频各不同），**不再全是同一种横卡**。
3. **色彩语义**：文章=蓝 / 图书=紫 / 论文=青 / 真题=琥珀 / 生词=绿；类型标签 = 色块 + 图形符号，替代黑底小贴片。
4. **信息架构**：每屏"主行动 → 内容 → 元信息"三层；一屏一主行动；杂志式编号与留白。
5. **语义化功能键**：图标 + 动词（「拍照识词」「直接批改」「换个说法找」）+ 微文案"点了会发生什么"。
6. **动效**：按压 scale、列表 stagger、数字滚动、图形生长、共享元素转场（首页大图 → 阅读器）、鲸鱼尾（已有）；全部走 transform/opacity，尊重系统"减少动态"。

**配图策略（我的主张）**：**自绘封面为主，真实图为增强**——真实图（RSS `og:image` / Open Library 封面）异步加载、2s 超时、本地缓存、失败静默回退到自绘封面（绝不空白/抖动）。理由：大陆网络不稳 + 版权，自绘可控且统一。
> 需要用户拍板：是否接受联网真实图（有失败率）；还是纯自绘（100% 可控）。
