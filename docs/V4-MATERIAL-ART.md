# 材料配图策略 · 研究存档(v4.3,2026-11-03)

> 用户诉求:"材料那些封面尽量能让 AI 抓取并配上材料自身的插图或者封面,不然整个软件太素了";
> 并问"AI 生图成本怎么样",倾向"网上本来就有书封,能不能爬"。
> 本文存档**实测证据、成本结论、已实现架构、明天拿到 Key 后的验证与调优计划**。

## 一、实测:用户网络下哪些图源可达(2026-11-03,本机 curl 实测)

| 图源 | 结果 | 说明 |
|---|---|---|
| 豆瓣读书联想接口 `book.douban.com/j/subject_suggest` | ✅ 200 | 返回 JSON,含封面 `pic` |
| 豆瓣图床 `img*.doubanio.com` | ✅ 200 | `/s/`→`/l/` 均可下,实测 25~250KB 真封面 |
| 360 图片搜索 `image.so.com/j` | ✅ 200 | JSON,`img` 原图常被防盗链,`thumb`(qhimgs1 CDN)可下 |
| 百度图片搜索 `image.baidu.com/search/acjson` | ⛔ 风控 | 返回 `Forbid spider access` |
| Bing 图片搜索 `cn.bing.com/images` | ✅ 200(HTML) | 结果页可达,但原图外链多为被墙 CDN,未采用 |
| Open Library covers `covers.openlibrary.org` | ⛔ 超时 | 不可达 |
| Google Books API / books.google.com | ⛔ 超时 | 不可达 |
| Wikimedia / Wikipedia REST | ⛔ 超时 | 不可达 |
| Gutenberg 官方封面 `gutenberg.org/...cover.medium.jpg` | ⛔ 超时 | **重要**:APP 老链路里公版书封面会因此加载失败 |
| Unsplash / Pexels / picsum | ⛔ 超时/403 | 不可达 |
| 火山方舟 `ark.cn-beijing.volces.com/api/v3` | ✅ 401(可达,需 Key) | 用户 App 主 API 走这里 → **唯一可用的 AI 生图通道** |

结论:国内网络下,"爬书封"是可行的(豆瓣),但**只有书**;非书材料(新闻/论文/
AI 生成文章)没有可靠免费图源 → 必须"抓取优先 + AI 生图兜底"。

## 二、成本结论

| 方案 | 成本 | 何时用 |
|---|---|---|
| 材料源自带图(feed media / og:image / cover_url) | 0 | 永远第一优先 |
| 豆瓣书封 | 0 | 书/书名型材料 |
| 360 图片(thumb) | 0 | 非书材料 |
| 方舟 Seedream 文生图 | **按张计费(量级:几毛/张,以方舟计价页为准)** | 仅当用户开启"抓不到时 AI 生成";一张生成一次、永久缓存 |
| 程序化印刷封面 | 0 | 全部失败时 |

**控成本的三道闸**:① 默认只抓取、AI 生成默认关;② 每张图生成后落盘缓存,
同标题同类型不再重复生成;③ 生图只在"抓取失败"且用户显式开启时触发。
下一步可加"每日生图上限"(建议默认 5 张/天,避免误开烧钱)。

## 三、已实现架构(本轮已落地)

```
ArtCover(展示层,lib/widgets/art_cover.dart)
  ├─ 有材料源图 → 直接展示(network);加载失败 → 触发抓取
  ├─ 无图 → 先显示程序化封面,后台 MaterialArt.resolve()
  └─ 拿到本地文件 → Image.file 原地替换(失败静默,绝不白块/转圈)

MaterialArt(服务层,lib/services/material_art.dart)
  ├─ 缓存:app support dir/material_art/matart_<hash>.jpg(同标题同类型永久复用)
  ├─ ① 豆瓣书封:subject_suggest → pic(/s/→/l/)→ 下载(Referer=豆瓣)
  ├─ ② 360 插图:image.so.com/j → 候选[img, thumb_bak, thumb] → 逐个试下
  ├─ ③ AI 生图:方舟 /images/generations,模型优先账号 /models 里的 seedream,
  │            否则 doubao-seedream-4-0-250828 / 3-0-t2i-250415 依次尝试
  └─ 护栏:同材料去重、全局最多 3 并发、必须 JPEG/PNG/WebP 且 ≥2KB 才落盘
```

设置入口:我的 → API 设置 → **04 材料自动配图**,三档:
抓取(默认)/ 抓取+AI 兜底 / 关闭(附"当前端点是否支持生图"的实时说明)。

已接入位置:继续读大卡、材料中心今日精读 + 材料库横卡、书架长按查看封面、
导入列表、发现页结果、练习设置材料卡、`AppHeroCard/AppWideCard`(`autoArt`)。

## 四、已知取舍 & 待改进(明天拿到 Key 后做)

1. **360 thumb 只有 240px**:列表够用,大图头卡偏糊。改法:大图位置优先原图
   (`img`,同一候选列表里先试),小图用 thumb;仍不行再 AI 生图。
2. **会搜到信息图/带字图表**(如光合作用示意图):下一步加"低质图过滤":
   - 关键词排除:`图解/信息图/流程/PPT/表格/截图`;
   - 尺寸过滤:已知宽高比极端(<1:2 / >3:1)跳过;
   - 可选:解码后算"白底占比 / 边缘笔画密度"粗略判文字图(轻量、不引新依赖)。
3. **豆瓣可能风控/限流**:已加 Referer/UA 与失败静默;量产时可加退避(429 时
   1 分钟后重试)与"第一次失败就短期禁用豆瓣"。
4. **AI 生图质量验证**:明天拿到 Key 后先做"单张试生图"入口(设置页加"试生成
   一张"按钮,展示结果 + 提示成本),人工确认风格prompt;再开批量。
5. **AI 生图计费口径**:以方舟控制台计价页为准;代码里不做价格承诺,UI 文案只写
   "按张计费,约几毛/张,以方舟账单为准"。

## 六、为什么不做"全部 AI 生成"

- 成本:材料库会持续增长,全量生成是持续支出;
- 准确性:真实书封 > AI 臆造封面(用户要的是"材料自身的图");
- 可靠性:生图接口会限流/失败;抓取+缓存+程序化兜底才是长期可用的链路。
