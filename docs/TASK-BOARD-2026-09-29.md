## 三、动手前的现状分析(根因,不是猜测)

### 3.1 第 1 条:为什么"材料中心"和"拍照识文"尺寸不统一

**实测截图逐像素量过**(Screenshot_20260929_125002.jpg,1260×2800):

| 区块 | 卡片水平外边距 | 左内容边距 |
|---|---|---|
| 拍照识文(AppCard,无 margin) | **0(通栏)** | 14 |
| 材料中心(AppActionTile→AppCard) | **0(通栏)** | 14 |
| 特色功能 · AI 生词定制文章(`Card(margin: h16)` + tilePadding 16) | **16** | **32** |
| 我的学习材料(同上) | **16** | **32** |

根因:`input_home.dart` 的滚动视图**没有页面左右边距**(`padding: EdgeInsets.only(bottom: Gap.lg)`),
所以前两张卡是通栏的;而后两个 Widget 各自硬写 `Card(margin: horizontal 16)` + 自定义圆角 12
+ `tilePadding 16`。同一个页面出现**两套卡片几何**(外边距 0/16、圆角 16/12、左内容边距 14/32)。

### 3.2 第 2(3) 条:搜索框"小说故事"是从哪来的

`category_material_screen.dart` `initState` 里 `_queryCtrl.text = _defaultQuery()`,
而 `_defaultQuery()` = **学习画像里的第一个兴趣词**;用户的画像兴趣就是"小说故事"。
所以"每次打开都挂着它"和"上次搜了啥"无关 —— 它压根不是搜索历史,是画像。**这是设计错误,不是缓存没清。**

### 3.3 第 6(2) 条:"改了出处还在未归类"的机制

`material_group.dart groupMaterials()`:书籍分类下 `material_path` 为空 → `groupPath = '未归类'`,
`source_page` 只决定**二级标签**。而 UI 上「未归类」分组**没有重命名按钮**
(`trailing: isUncategorized ? null : IconButton(...)`,见 `my_materials_section.dart`),
二级卡片上的铅笔只调 `updateSourcePageByIds`(只写 `source_page`)。
→ 用户改页码 = 只改了二级标签,**没有任何入口能把 `material_path` 补上**,所以永远出不去「未归类」。

### 3.4 第 2(2) 条:"之前提的两个需求完全没有"的实际状态

| 需求 | 材料原文阅读器 | AI 改写材料(推荐详情/存为文章) | 特色功能生词成文 |
|---|---|---|---|
| 标题「中文(英文)」 | 部分(仅公开源命中标题有 AI 译名) | ❌ | ❌ |
| 逐段英中对照翻译 | ✅(AppBar 图标,容易看不见) | ❌(只有整篇旧翻译) | 只有整篇旧翻译 |
| 点词 → 询问 AI / 收藏 | ✅(底部弹层) | ❌(纯 Text,点不了) | ❌(纯 Text,点不了) |
| 长按选中多词 → 两个选项 | ❌(走系统复制菜单) | ❌ | ❌ |

→ 结论:功能是"三套阅读器各写一份,只有一套有"。本批的修法是**抽出共用阅读正文组件**,
让三个阅读器用同一份(点词/选词/翻译/收藏),以后加功能不会再"只加在一个地方"。

### 批次 A(commit `047ee65`)—— 第 1 条 + 第 6 条

**第 1 条:输入页卡片几何统一**

**第 6(1) 条:能直接删分组**

- 一级分组与二级(页码/章节)都加了「删除整组(N 个生词)」:二次确认 + 批量删除
  (`deleteVocabularies` 单事务,不是 N 次单删);
- 另给「**解散分组**」:词保留、`material_path` / `source_book` 清空 → 回到「未归类」;
- 顺带修:一级分组的右上角铅笔占用了 `ExpansionTile.trailing`,**展开箭头被顶掉**
  (用户看不出这行能展开)。现在恢复箭头,四个操作(重命名/改出处/解散/删除)
  收进展开区底部一行,带文字标签。

**第 6(2) 条:"编辑了出处还在未归类"**

- 根因:「未归类」的词 `material_path` 为空,而 UI 只能改 `source_page`
  (`updateSourcePageByIds`),**没有任何入口能写 material_path** —— 改页码只换了个二级标签。
- 现在:未归类的分组/二级都提供「**归入材料…**」,一次写 `material_path` + `source_book`
  + 页码(`buildMaterialPath` 强制两级),填了材料名就真的移出未归类;
  材料名为空时当场提示"没有材料名它就还是「未归类」",不做"保存成功但什么都没变"。
- 新增 `DatabaseService.detachMaterialPath` —— 显式置 NULL。为什么不复用
  `updateVocabulariesCategory`:那个方法的 `null` 语义是"这一列不改",表达不了清空。

### 教训:加插件依赖后必须真的 `flutter build apk`

本批原计划引入 `file_picker` 做"从文件导入",**两版都构建不过**:

| 版本 | 失败原因 |
|---|---|
| 11.0.3 | 它的 `android/build.gradle` 有 `if (!isAgp9OrAbove) apply plugin: 'org.jetbrains.kotlin.android'` —— 本项目是 **AGP 9.0.1**,于是它**不 apply Kotlin 插件**,可它源码是 `.kt` → Kotlin 源根本不编译,报「找不到符号 FilePickerPlugin」 |
| 10.0.0 | android 侧是 Java 源码(能过 Kotlin 那一关),但它把 `compileSdk` 写死 **34**,与 `flutter_plugin_android_lifecycle` 要求的 **36** 冲突(AAR metadata 检查失败) |

而 `flutter analyze` / `flutter test` **全程都是绿的** —— 这两个命令根本不会碰 Android 构建。
最终改成自写原生通道(与 v2.6 的 `app/open_url` 同一套写法),既过了构建,也少了一个依赖。
已写进交接文档 §7 的教训清单。
