## v2.3.1 — 诊断增强:让"哪个源能用/小组件同步没同步"在 App 里直接看得见

这一版没有新功能,只做两件事:**把误导人的提示改对**,**把只在你手机上才看得见的状态摊到 App 里**。

### 🔍 一、诊断信息新增两段(截图就能定性)

「我的 → 诊断信息」现在多了:

```
── 材料源(最近一次可用性) ──
✔ npr         最近可用 · 3 分钟前
✖ bbc_le      上次失败 · 2 小时前 —— 网络中断:HandshakeException…
— ted         还没试过

── 桌面小组件 ──
已添加 1 个 · 最后同步 今天 08:12
```

为什么加:内容源能不能用**取决于你的网络**,平时在 App 里看不见;小组件的"已添加但没同步"和"压根没添加"也是两种完全不同的故障。以后遇到问题,**截这一屏**我就能一次看清,不用来回问"你点的是哪个源"。

### ✏️ 二、修掉一句会带错方向的提示

实测:BBC 的失败其实是 **TLS 握手被中断**(不是超时),而旧代码对"连接被中断"一律提示"大文件(公版书全文)首次抓取可能被中途掐断,重试一次通常就好" —— 你请求的明明是一个 RSS 列表,却被暗示是"整本书太大",完全找错方向。现在分场景:

- 列表/正文请求被掐断 → "该来源在当前网络下可能不可直连(部分网络会重置连接),换一个来源或稍后重试";
- 只有整本书全文才说"重试一次通常就好";
- 超时提示里的秒数也跟着实际用的超时走(全文是 90 秒,不再是写死的 20 秒)。

### 🧪 三、材料源端到端自检工具(给你的,也给我的)

新增 `tool/probe_sources.dart`:用 **App 自己的抓取与解析代码**跑一遍"列表 → 抓正文 → 切块",因为"能连通"不等于"解析得出条目"(源站改版会让列表变空,那在 App 里看起来和"连不上"一样)。

本次运行结果(2026-09-24):

```
npr         OK 3 条 1.6s   ↳ 正文 OK 1.7s  chunks=1 words=590
arxiv       OK 3 条 1.2s   ↳ 正文 OK 0.8s  chunks=1 words=276
gutenberg   OK 3 条 0.9s
bbc_le      FAIL 1.0s  网络中断:TLS 握手被终止
voa_le/ted/wikipedia  FAIL 20s 超时
```

也就是说:**默认源 NPR 的"列表 → 正文"这条链是通的**(这正是你点「分析并读」走的那条路)。

### ⚠️ 已知限制

1. 「检测可用源」与自检工具报告的结论**取决于你所在网络** —— 移动数据 / 不同宽带可能有差异;我这边(NPR/arXiv/Gutenberg 通,BBC/VOA/TED/Wikipedia 不通)只是**一个样本**,你那边以 App 里点出来的为准;
2. 小组件外观仍需你在桌面上确认;
3. 「跟读」按你的意思不排期;「每日提醒」等你定(需要通知包)。

### 想请你验证

1. 你之前遇到的**材料中心**:现在打开应直接进 NPR 且有条目;点一篇「分析并读」走完读前卡 → 阅读器;
2. 顺手看一下「我的 → 诊断信息」新增的两段是不是你想看到的信息(如果还想看别的,告诉我加);
3. 小组件:添加后回桌面看内容、点它打开 App,再回「桌面小组件」页点「同步并预览」核对数字。
