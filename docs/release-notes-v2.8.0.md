## 1. 「追加图片」卡死闪退 —— 找到三条真因

不是偶发,是必然:
1. **追加时拿的是 12MP 原图**(首页相册那条一直压到 1024px,只有追加没压)→
   单张解码就要约 48MB,再转 base64、再切块,**3~4 张就把内存撑爆** ——
   表现就是"卡一下然后闪退";
2. 每次识别成功都会**重建全部图片锚点**,上一轮结果的界面被迫整棵重建;
3. 图片列表为空时会去读第 0 张(越界)。

修法:追加也压到 2600px/画质 92(与识图管线一致)、总张数上限 10、单次追加上限 4、
锚点只补不重建、失败变成可重试的提示(已有结果不会丢)。

## 2. 涉及中文时词汇板块乱 —— 是"一个内容两张卡"

**根因**:页边那种手写中文批注,以前是**单独占一张卡**,而它旁边的英文词也会各出一张
—— 于是同一份内容出现两张,而且一张中文当头、一张英文当头,看着又乱又重复。

**现在**:中文批注会**并到对应的英文词条上**,卡片上多一行「页边批注:xxx」;
找不到对应英文词时,把它转成"英文当头"(结构与其它卡完全一致),不再出现"有的先中文"。

## 4. 复习模式

**4(1) 点「认识」卡住** —— 真 bug:从下一张退回来时,那个词已经被标成「认识」,
再点「认识」时代码直接跳过了"翻到下一张"这一步。现在照样往下走(计数仍不重复)。

**4(2) 单词被拆成两行** —— 真 bug:卡片背面的等级徽标**抢了宽度**,
`primordial` 被挤成 `primordi / al`。现在单词保证一整行(过长自动缩放),
徽标移到词下面;正面补上了出处与"点卡片看释义"的提示,卡片不再大半是空白。

## 6. 材料中心

先说调研结论(按你"好好查一下别人怎么实现的"):你截屏的那款是**扇贝阅读**。
我把 8 款同类软件的官方截屏逐像素量了一遍 + 在本机实测了每个免费图源 ——
**Wikipedia / Openverse / Gutendex / Open Library 在你这台机器上全部不可达**
(`upload.wikimedia.org` 连图片都拿不到),只有 Gutenberg 封面和 RSS 自带图能用。
**所以截屏里那种手绘水彩插画是人家自有版权图库的,公开图源给不了那个质感** ——
这条要你拍板(见文末)。

已做到的:

**(1) 今日推荐中文标题** ✓ 标题一律「中文(英文)」(推荐条目也翻了)。

**(2) 视觉与信息架构**(你说"整个软件全是字唉"):
- 现在每张卡都有**配图**(有真图用真图:公版书封面 / RSS 的 media:content;
  没有就用**程序化封面** —— 按标题稳定取色 + 首字母,零网络零版权,永远不会白块);
- 新增「**今日精读**」大卡:16:9 配图 + 题材/Lv 标签 + 英文标题 + 中文副标题 +
  元信息 + 整宽的「开始阅读」按钮;打开前会**先分析这篇的难度**,卡片上的数字是真的;
- 元信息比对标软件**多给**:等级 Lv + **已知词汇覆盖率** + 时长 + 词数 + 句数 + 口音;
- 「**发现更多**」:6 个题材 tab(科学与技术/商业与政治/健康与生活/文化与艺术/
  旅行与体验/语言与学习),**公版书 + arXiv + 外媒三路并行**检索,一屏铺满图文卡;
- 材料库也改成图文卡(缩略图 + Lv + 认知率 + 难度适配标注)。

**(3) 逐段翻译"无法使用"** —— 不是坏了,是慢得等于不可用:以前要**把整篇翻完才显示**,
一本书要几十次请求,所以永远在转圈。现在**按需翻译**:打开先翻附近 3 段,
往下滚自动接着翻,底部显示「翻译中 3/40」,某一段失败只影响那一段(可就地重试)。

**(4) 流式「查阅了 xxx」** ✓ 不再是一个转圈。每一步都是**真实发生的**:
「按「科学与技术」找材料」「正在检索 3 个来源」「Gutenberg:找到 10 篇 1/3」
「NPR:没连上(超时)」「正在把 12 个标题翻成中文」「**查阅了 22 篇 · 用时 4 秒**」。

**(5) 材料太少 + 分类区 AI 对话** ✓
- 题材检索走"公版书 + 论文 + 外媒"三路,一次能拿到二十来条;
- 每个分类页右上角新增「**跟 AI 说需求**」:给你 6 个可直接点的方向
  (再简单一点 / 换短一点 / 要能听的 / 难度拉高 / 换个题材…),也可以自己写,
  AI 读懂后换检索词重搜一遍 —— 不用自己想英文关键词。
