## 二、根因（三层，不是零散 bug）

1. **服务层契约缺失**：数据库/存储写方法一律"吞异常 + 返回 void"，调用方拿不到成败信号
   → 所有"失败也弹成功"都从这里来。修法不是逐处加 try/catch，而是让**写方法返回成败**。
2. **页面状态缺"失败"这一维**：`_mine` 只有 loading/有数据/空 三态，没有 error 态；
   `_running` 只有跑/没跑，没有"可取消"。修法：加 `_mineError` 与取消 token。
3. **身份与成本口径没统一**：URL 归一有两套、入库身份用标题、花费只算一半。
   修法：抽 `url_key.dart` 单一归一；入库优先 URL；花费文案如实标注口径。

## 三、修复方案（本轮做什么，按风险从低到高）

### B1 正确性（本轮做）

1. **服务层返回成败**（P2-1）
   - `DatabaseService.setMaterialTitleCn` → `Future<bool>`（true=写成功，false=异常）；
   - `DatabaseService.deleteMaterial` → 保持 `Future<int>`，异常返回 `-1`（0 仍表示"没有这行"），
     **调用方全部改为 `< 0` 判失败**（`material_library_screen` / `material_channel_screen` 等）；
   - `MaterialChannelStore.saveRun / addSavedMaterial / removeSavedMaterial / addHiddenMaterial`
     → `Future<bool>`；频道页据此提示"保存/移除失败"。
2. **「我的」错误态**（P2-2）：`_loadMine` 记录 `_mineError`；失败时「我的」显示
   「读取失败 · 重试」卡，而不是空态。
3. **快照上限**（P2-3）：`MaterialChannelStore` 增加 `maxSnapshotItems = 120`；
   append 超限只保留前 120 条（按首次出现顺序）；频道页在 `_items.length >= 120` 时
   **禁用「继续找更多」并说明原因**，避免"付了钱结果被丢"。
4. **入库身份用 URL**（P2-4）：`MaterialLibrary.ingestText` 在 `url` 非空时
   `source_id = 'url:<归一key>'`，否则退回 `'title:<标题>'`；老数据不迁移（新老身份并存可接受）。
5. **URL 归一统一**（P2-9）：新增 `lib/services/url_key.dart`（`normalizedUrlKey` 单一实现 +
   `isSameUrl`），`material_channel.dart` / `material_discovery.dart` 都改为引用它，删掉重复实现。
6. **花费口径如实**（P2-5）：统一文案「官方搜索约 X 元（模型调用未计）」，不虚报也不装全知。
7. **付费刷新确认**（P2-7）：发现 Tab 已有结果时点 AppBar 刷新 → 底部确认条/dialog：
   「再找一批会重新调用官方搜索（约 0.0X 元/次），确定？」；空态首次找不弹。

### B2 体验（下一轮，需先给用户看效果）

8. **取消检索**（P2-6）：`discover(..., bool Function()? shouldCancel)` 在每次抓取前检查；
   频道页 `_running` 时头部出现「停止」，点了丢弃未完成结果但**已花费照记**，并明确提示。
9. **需求设置独立页**（P2-8）：`_openNeedSettings` 不再进旧浏览页，改为轻量
   `MaterialNeedSettingsScreen`（只改需求/难度/目标/形式偏好，不带 300 条材料列表）。
   这是新增页面，按用户规矩先出方案再落。
10. **频道页 widget test**（P2-10）：注入假 store（或 Hive 临时 box）测：
    改标题失败提示、删除失败提示、`_loadMine` 失败错误态、快照上限禁用按钮。
