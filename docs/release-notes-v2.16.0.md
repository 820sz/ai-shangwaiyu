# ReadFlow v2.16.0 · 输入重构：需求驱动 + AI 找材料 + 难度自选 + 译文留住

> 批 2（2026-11-01）：把「输入」从"上传工具页"改成"读+听"的入口，
> 并按你的批注把 AI 找资源、难度自选、阅读器翻译真正做进去。

## 更新内容

1. 输入首页第一屏改成「今天读什么」：有在读材料就接着读，没有就按你的需求去材料中心找；拍照/导入降为第二层级的工具。
2. 新增「我的需求」条：目标和难度档一眼可见，点开就能改。
3. 难度档可以自己选：i+1 舒适 / i+10 挑战 / i+100 快反馈（生词多、读着费劲但爽，适合短期冲量），改完全 App 同步。
4. 新增「AI 按我的需求找材料」：用中文说想要什么，它会出检索计划、公开源 + DeepSeek 官方搜索一起找、抓回正文算出真实难度，并告诉你为什么推荐这一篇。
5. 阅读器翻译翻过一次就永久留下：重进阅读器译文还在，不再从 0 重翻，也不重复花额度。
6. 翻译出问题能看到原因了：我的 → 诊断信息新增翻译槽位/模型与最近 3 条失败原因；阅读器控制条显示翻译实际用的槽位。
7. 阅读器翻译被模型截断时会明确提示「输出被截断」，不再含糊。

## 技术细节

- 输入偏好统一层 `lib/services/input_prefs.dart`：难度档 / 多选目标 / 兴趣 / 黑名单读口径统一；难度区间**直接复用 MaterialBand**（0.98 / 0.90），不另立数字；升/降档建议算法数据不足时返回 null（不猜）。
- 发现流水线 `lib/services/material_discovery.dart`：需求 → 检索计划 → 公开源 + DeepSeek 官方 `/v1/tools/search` `/v1/tools/fetch` → 抓正文 → 本地难度分析 → 按难度档/权威度/相关性排序 → 可解释推荐理由；官方搜索花费可见（5 元/千次成功请求），无 url 结果直接丢弃。
- 新页面 `lib/screens/input/material_discover_screen.dart`（检索时间线 / 难度档切换 / 结果卡），入口在输入首页「AI 帮找」与材料中心「更多找法」。
- 阅读器翻译落库：新增 `material_translations` 表（dbVersion 19→20，source_text 快照防错位），翻过即存、重进即读；`finish_reason=length` 明确提示截断；翻译失败进诊断缓存（脱敏，不含 Key）。
- 验证：`flutter analyze` 0 error / 0 warning（9 条存量 info）；全量测试 **1262 passed + 1 skip + 1 已知假失败**（`profile_card_test` 的 Hive 假时钟问题，与 App 无关）。
