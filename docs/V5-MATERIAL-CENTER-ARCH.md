# 材料中心架构升级方案（v5 · 讨论稿，先定架构再动前端）

> 用户 2026-11-04 19:30 需求原话摘要：
> ① 材料中心不要把"功能区 + 子功能区"全塞一个界面，首页只给**大功能分区**，点进去再给子分区；
> ② 功能角色混乱要理清（首页"我的需求"vs 材料中心"我的需求"；"今日精读"vs"今日推荐"；
>   首页"AI找材料"vs 材料中心底部"还有更多找法"里又嵌套已有功能）；
> ③ 正确的是：**按需求**，在需求之上衍生几种**并行方向**——按题材 / 按形式 / 按场景；
>   这些分类不是互斥的，可以**多选**后推送垂直精准材料；每个大分类里再分子类，然后出材料；
>   材料中心首页只保留"今日精读"（且支持精读文章左右切换）；
> ④ 材料库（点击过/浏览过的材料）要支持**编辑、删除、收起**；
> ⑤ 书架两种形态可切换：3D 轮播书架（能看到书侧标题）/ 详细书架（能看到书封）；
> ⑥ 阅读器翻译 bug：先上议程，暂不做（**已定位并修复，见文末**）。
>
> 本文只做**架构与规划**，确认后再开始前端改造。

## 一、现状审计（为什么会乱）

### 1. 材料中心一屏塞了 6 个区块（层级混在一起）

`material_center_screen.dart` 当前顺序：
`我的需求(hero)` → `01 今日精读` → `02 按分类找材料(6 题材网格)` → `03 今日推荐(来源胶囊+横卡)`
→ `04 书架` → `05 材料库` → 底部 `还有更多找法`。

结果：
- 同一屏里出现**三种层级**：需求（筛选条件）、分类入口（导航）、材料列表（内容）；
- "今日推荐"和"今日精读"都是"推一篇"，角色重叠；
- 书架/材料库是"我的资产"，也被塞在"找材料"页里，和"书架页"重复。

### 2. 入口重复 / 嵌套重复

| 重复点 | 位置 A | 位置 B | 处理 |
|---|---|---|---|
| 我的需求 | 输入首页 · 难度胶囊（i+10/四六级） | 材料中心 · 我的需求编辑卡 | 合并为**唯一需求设置**，首页只读摘要+跳转 |
| 按需求找材料 | 材料中心 · 我的需求 → AI 按需求找 | 材料中心底部「还有更多找法」→「AI 按需求找材料」 | 收进 **按需求** 大分区，删掉嵌套入口 |
| 按形式找材料 | 「还有更多找法」→「按你的水平找材料」（教材/书籍/外刊/碎片文章/其他） | 单独 `CategoryMaterialScreen(category)` | 提升为一级 **按形式** 大分区 |
| 按题材找材料 | 材料中心「02 按分类找材料」网格 | 「还有更多找法」→「发现更多(按题材检索)」 | 提升为一级 **按题材** 大分区，删掉嵌套 |
| 今日推荐 | 材料中心 `03 今日推荐` | 各来源页/分类页内容 | 删除一级区块；"来源最新"并入按形式/按题材的二级页 |

### 3. 分类维度混杂

- 现有"按分类找材料"= 题材（科学技术/商业政治/…）；
- 现有"按你的水平找材料"= 形式（教材/书籍/外刊/碎片文章/其他）+ 难度；
- 现有难度档（i+1/i+10/i+100）又是**筛选条件**，却被放到首页当入口；
- **场景维度完全缺失**（应试/出国旅游/生活聊天/生产力英语）。

### 4. 材料库只读，不能管理

`_buildShelfCard()` 只有"点开阅读器 / 打开原文链接"两个动作；`DatabaseService` 已有
`deleteMaterial` / `setMaterialGroup` / `setMaterialTitleCn` 能力，但界面上没有暴露。
→ 用户"点过的材料越堆越多，既不能改中文名、不能改分类、不能删、也不能收藏/归档折叠"。

### 5. 书架形态单一

`BookshelfView` 是平面木架（v2.13 因裁剪 bug 回退了 3D 透视）。用户要两种形态：
3D 轮播书架（书脊标题可见）与详细书架（书封网格）可切换。

## 二、目标信息架构（IA）

### 2.1 材料中心首页（只有 4 个入口 + 今日精读 + 材料库）

```
┌ 材料中心 ────────────────────────────┐
│ [今日精读]  大卡(封面/标题/词数/难度)      │
│    ← 左右切换 3~5 篇 · 「去读」        │
│                                     │
│ [按需求找材料]  当前需求摘要 → 进入         │
│ [按题材找材料]  6 个题材大卡              │
│ [按形式找材料]  教材/书籍/外刊/论文/真题/碎片/其他 │
│ [按场景找材料]  应试/出国旅游/生活聊天/生产力 │
│                                     │
│ [我的材料库]  128 篇 · 管理 >            │
└─────────────────────────────────────┘
```

- **只保留一个内容推荐位**：今日精读（支持左右切换，见 Q3）；
- **首页"我的需求"难度胶囊**：只读展示 + 点击进入「按需求找材料」（不再就地编辑）；
- **今日推荐 / 书架 / 更多找法** 从首页一级区块移除：
  - 今日推荐 → 按形式/按题材二级页的"最新"排序；
  - 书架 → 保留独立"书架"页（底部 tab 或我的页入口，见 Q1）；
  - 更多找法 → 删除弹层，能力拆进对应大分区。

### 2.2 统一二级浏览页（四个维度共用一套模板）

```
┌ 按题材 / 按形式 / 按场景 / 按需求 ─────────────┐
│ 顶部:维度名 + 当前需求摘要(难度/目标/已选条件)     │
│ 子分类多选: [科技报道][科研成果][科普书]…（可多选） │
│ 可选筛选: 难度档 / 来源可用性 / 只看可离线        │
│ 材料列表: 横卡(标题/词数/难度/来源/进度) + 无限滚动  │
│ 底部: 没找到? 「让 AI 按这个方向补长尾」           │
└─────────────────────────────────────────────┘
```

- 点击大分区 → 该维度二级页（子分类 chips + 材料列表）；

- 每个维度都支持"AI 补长尾"（把当前选择作为提示词，走现有 AI 搜索链路）。

## 三、材料库管理（新增页面）

`MaterialLibraryScreen`（从材料中心/我的入口进）：
- 列表：材料卡（中文名/英文名/来源/词数/进度/难度/分组）；
- 管理动作：
  - **编辑**：中文标题（`setMaterialTitleCn`）、分组/分类（`setMaterialGroup`）、
    （可选）难度标签；
  - **删除**：二次确认，删 `materials` + 关联进度/译文（`deleteMaterial` 已处理），
    可选择"连阅读进度一起删 / 只删材料记录"（见 Q9）；
  - **隐藏/收起**：不参与推荐与列表计数（隐藏状态存 Hive 黑名单，不动 DB），
    可切到"隐藏区"恢复；
  - **批量**：多选后批量删除/移动分组/隐藏；
  - **分组折叠**：按 来源/时间/分组 折叠（默认折叠除"最近"外的分组）。
- 与书架关系：书架 = 用户主动"摆上书架"的精选；材料库 = 所有浏览/导入过的材料（含书架），
  两者不重复展示（书架页只显示书架表；材料库显示全部）。

## 六、阅读器翻译 bug（已定位并修复，本阶段不改视觉）

用户截图(11/04 00:16，格列佛游记)里界面出现：
`已翻 4/[ReaderUnit(chunk=0, para=0, 18字), ReaderUnit(...)…]`。

根因：`material_reader_screen.dart:664`
`'已翻 ${_translations.length}/$_units.length 段'` —— `$_units.length` 在 Dart 里
先插值 `_units`（整个列表）再拼字面量 `.length`，于是把整份 ReaderUnit 列表 dump 到界面。
**已修为 `${_units.length}` 并提交**（commit `fix(阅读器): 翻译进度…`）。
阅读器其他问题（翻译卡顿、范围选择、对照体验）列入 P5 单独 agenda，本阶段不碰。
