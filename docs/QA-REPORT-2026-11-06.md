2. **「我的」数据源被 `shelf(limit: 300)` 截断**：`_reloadAll`/`_loadMine` 用 `MaterialLibrary.shelf(limit: 300)`（:619-623、:679）再与 savedIds 求交；材料库超过 300 条后，较早保存的材料**静默消失**（`shelf` 按最近更新倒序）。修：按保存 id 批量查（`getMaterialsByIds`），不要用全局最近 300。
3. **到快照上限后仍可付费且结果被静默丢**：`saveRun` append 超限保留**最早** 120 条（`MaterialChannelStore.saveRun` 当前截断逻辑，`sublist(0, maxSnapshotItems)`）；「继续找更多」按钮会禁用（screen :1778/:1812-1826），但 **AppBar 刷新**（`_onHeaderRefresh` → `_startDiscovery(more:false)`，当前 :1406-1420）没有 atCap 检查 → 已达 120 条后点刷新仍付费检索，新结果写快照时被丢掉（UI 内存里短暂可见，重启即消失）。修：达到上限时刷新也拦截，或截断保留最新/提示先清理。
4. **入库不落封面**（同 §1-1）：`ingestText` 无 cover_url、`_ingestToLibrary` 不传 imageUrl → 「我的」/书架/阅读器无真封面。P2。
5. **「刷新」语义=追加**（P3）：发现 Tab AppBar 刷新走 `_startDiscovery()`（more=false、`hadItems=true` → append），不清旧结果、只加新结果，与按钮名「刷新」不一致（WIP 已加付费确认，但语义仍混）。建议改名「再找一批」或真刷新=清空重搜。
6. **`planNextQueries` 失败后仍付费重跑旧词**（P3）：WIP 前 master :645-658 失败置 `extraQueries=[]`，随后 :661-671 仍用原 queries + excludeUrls 去搜 → 几乎必被排除，白花官方 Fetch。当前代码结构类似（`_startDiscovery` 中 planNextQueries catch → 空列表继续）。建议失败即中止并提示。
7. **分页纯函数无测试**（P3）：`materialChannelPageSize/PageCount/Clamp/Range`（:115-160）+ `_pageGroupSlices`（:1855-1879）无 test（grep 0 命中）。补 4 组纯逻辑测试可防后续漂移。
