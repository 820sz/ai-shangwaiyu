## v2.3.2 — 修掉「材料库点不开」和「入库了却看不见」(整链路测试挖出来的)

这一版是**给主流程补了一个端到端测试**之后的产物:测试一跑,立刻抓出三个之前所有单测都覆盖不到的真 bug —— 单测各自都绿,但用户真正走的那条路是断的。

---

### 🐞 一、材料库里每一份材料的 id 都是 0(点了打不开)

材料库列表的 SQL 只把主键输出成 `material_id`,而界面读的是 `id` —— 于是**每一条的 id 都取到 0**。表现:材料库里点任何一份材料,都会去打开"id = 0"的材料(打不开 / 报错)。

这个缺陷从 v2.0 就在,只是材料库经常是空的,一直没暴露。现在查询同时带出 `id`,顺带补齐了 `source` / `url` / `audio_url`。

### 🐞 二、入库了却没打开过的材料,在材料库里完全看不见

材料库查询原来用 `material_progress` **INNER JOIN** `materials`(从"有阅读进度"的行出发),所以**只要一份材料还没进过阅读器,它就不出现在书架里**。

实际场景:粘贴/入库一份材料 → 这次没读 → 回到材料中心 → "还没有材料" → 用户以为导入失败了。

现在改成 `materials LEFT JOIN material_progress`:材料库里**所有材料**都在,没读过的显示"未开始";排序按"读过的按最近阅读时间,没读过的按入库时间"。学习助理里"在学 N 份"的统计同时改成只算真正有进度的,口径不变。

### 🐞 三、学习助理页可能被一次 Hive 读失败整页炸掉

快照加载器的文件头写着"任何一项读取失败都降级,绝不让导师页白屏",但**读学习者模型那一步没有包进降级** —— Hive 读异常会直接抛到界面。现在读了兜底:模型读不到就按空模型继续(诊断少几条结论,页面照常打开)。

### ✏️ 四、顺手修的文案

`按 你的自评:9000 词(仅供参考)` → `基线:你的自评 9000 词(仅供参考)`(原写法断句不清)。

---

### 🧪 新增:整链路回归测试(`test/learning_flow_test.dart`)

用**真 SQLite** 把用户真机走的那条路整条跑一遍:

> 材料入库(难度分析)→ 书架能看到 → 阅读(收词/进度/会话)→ 标记读完 → 读后测验出题与判分 → 错词进错误档案 + 复习状态回退 → **今日复习队列真的排得出这个词** → 学习助理诊断照常出结论且每条带依据

外加两个边界:坏 `difficulty_json` 不炸链路、配额设"只复习不加新词"时队列真的不排新词。

这轮的价值就在这里:**四个用例,抓出三个真 bug**。后面几条主路径(复习、听写、导出/恢复)也会照这个法子各配一条。
